# 迁移到 iced：纯 Rust UI 方案

目标：把 OpenCLion 的界面从「Tauri + React/Web」换成「iced 0.14 + 纯 Rust」，**UI 与功能与现在的 web 版一致**，不再依赖 webview。

本文是**方案与排期**，不是承诺。第 2 节的数据来自仓库实测（2026-11-16）。

---

## 1. 目标与非目标

**目标**

1. 一个不加载任何 HTML/JS 的可执行文件：编辑、项目树、Git、调试、终端、设置全部由 iced 绘制。
2. 功能对齐：现有 27 个工具窗、323 个 action、14 个设置页、10 种编辑器、16 个状态栏项，全部有对应实现或明确降级（见 §6、§9）。
3. 现有 Rust 领域层零重写：`ide-*` 35 个 crate 原样复用，`tauri::command` + specta 换成普通函数调用。
4. 在**无 GPU**（ASPEED + llvmpipe）机器上可用：走 iced 的 `tiny-skia` 软件渲染器，帧时间目标见 §4 的验收标准。

**非目标**

- 不保留 webview（因此「Web」工具窗、基于 HTML 的 markdown/mermaid 渲染需要替代，见 §9）。
- 不追求像素级复刻 CSS：以「视觉语言一致」为准（同样间距、色板、图标、层级）。
- 不换掉 Tauri 以外的平台能力（菜单/托盘/更新器继续用 `tauri` 的窗口与系统集成层，或换成 `winit` + 自研，见 ADR-1）。

| Tauri 命令 / invoke 调用点 | 450 / 856                                             |

## 3. 目标架构

```
┌─────────────────────────────────────────────────────────────┐
│ openclion-shell (bin)                                       │
│   winit 窗口 / 菜单 / 托盘 / 更新器 / 单实例 / 深色模式      │
├─────────────────────────────────────────────────────────────┤
│ openclion-ui (新)  iced 0.14                                │
│   App(State) ── Message ── update() ── view() -> Element     │
│   ├─ workbench: pane_grid 布局、工具窗、标签、状态栏、通知   │
│   ├─ widgets:   Tree / Table / Tabs / CodeEditor / Dialog    │
│   ├─ theme:     Tokens（由现有 CSS 变量生成）                │
│   ├─ keymap:    现有 keymap JSON → iced 键位绑定（带 when）  │
│   └─ i18n:      现有 locales JSON                            │
├─────────────────────────────────────────────────────────────┤
│ features/* (每个 = State + Message + update + view)         │
│   project-tree, search, vcs, run, debugger, terminal,       │
│   settings, tools, agents, database, http-client, …         │
├─────────────────────────────────────────────────────────────┤
│ ide-* （不变，35 个 crate）                                  │
│   ide-index / ide-lsp / ide-dap / ide-vcs / ide-search /    │
│   ide-terminal / ide-syntax / ide-workspace / …             │
└─────────────────────────────────────────────────────────────┘
```

**核心变化**：`src-tauri/src/commands/*.rs`（450 个 `#[tauri::command]`）变成 `openclion-ui` 直接调用的 Rust API；`src/bindings.ts`（6,000 行生成物）与 IPC JSON 序列化整体消失，事件走 `tokio::sync::broadcast` / `crossbeam` 通道 + iced 的 `Subscription`。

## 4. 关键技术决策（ADR）

| #     | 决策                                                                       | 理由                                                                                        | 备选与否决理由                                                        |
| ----- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| ADR-1 | **保留 `tauri` 作为窗口/菜单/系统集成层，只换渲染与 UI**                   | 已经有菜单、托盘、单实例、更新器、`.desktop`、窗口状态、X11 焦点等 15 个可用的平台适配      | 换成纯 `winit`：要多写 10+ 个平台适配，收益为零                       |
| ADR-2 | 渲染器 **`tiny-skia`（软件）优先，`wgpu` 作为可选**                        | 目标机器无 GPU；iced 默认两者都编译，运行时可切换                                           | 只用 wgpu：在 llvmpipe 上更慢甚至不可用                               |
| ADR-3 | UI 状态用 **Elm 架构（State/Message/update/view）**，每个 feature 一个模块 | 与现有 zustand store + action 的边界几乎 1:1；便于并行开发                                  | 全局可变单例：跨 feature 的消息风暴难调试                             |
| ADR-4 | 编辑器**自研**，基于 `ropey` + `cosmic-text` + iced 自定义 `Widget`        | LSP、语法、折叠、outline 已全部在 Rust（`ide-lsp`/`ide-syntax`/`ide-text`）；只缺渲染与输入 | 用 iced `text_editor`：无虚拟滚动、无装饰、无多光标，改造成本高于自研 |
| ADR-5 | 复用 **`tauri-specta` 之外**：删除 specta/generated bindings               | 命令变直接调用后不再需要类型生成                                                            | 保留：维护两套类型                                                    |
| ADR-6 | 图标继续用 **SVG**（`iced` 的 `svg` feature）                              | 833 个图标零转换；颜色用 `Svg::color` 覆盖                                                  | 转 PNG：体积与缩放都差                                                |
| ADR-7 | 对话框用 **`rfd`**（原生 GTK/portal），确认框自绘                          | 与现在 Tauri dialog 行为一致（我们已切到 xdg-portal 后端）                                  | 自绘文件选择器：跨平台代价大                                          |
| ADR-8 | 本方案**用分支 + 特性开关并行推进**：`iced` 分支，CI 同时跑两套            | 迁移跨年，不能打断现有发布                                                                  | 一次替换：风险不可控                                                  |

## 5. 里程碑

人月按「一名熟悉 Rust GUI 的工程师」估算；并行开发可压缩日历时间。

### M0 · 可行性验证（0.5 人月，1–2 周）

- 一个 iced 0.14 窗口：`pane_grid`（3 栏）+ 状态栏 + `text_editor` 可输入中文（IBus）。
- 在同一台无 GPU 机器上跑 `tiny-skia`，**实测**：滚动帧时间、输入延迟、字体渲染、IME 提交/光标位置。
- 产出：`iced-spike` 分支 + 一页实测报告（与 CEF 的 20ms/帧对比）。

**验收**：1440×900 窗口滚动 ≥ 50 fps；中文输入正确提交、光标位置正确；`cargo build` 不引入 webview。

**决策门 1**：若软件渲染明显慢于当前 CEF（>1.5× 帧时间），本方案暂停，转「继续优化 CEF」。

### M1 · 外壳（2.5 人月）

窗口与多窗口（主窗 + 设置窗）、`pane_grid` 布局与拖拽、工具窗容器（27 个占位）、标签栏、状态栏（16 项）、命令面板、通知、主题（Tokens）、i18n、键位（when 上下文）、欢迎页、设置框架（14 页的空壳）。

**验收**：能打开工程、在空壳工具窗之间切换、键位与命令面板可用；与现有版本截图同布局（人工比对）。

### M2 · 编辑器核心（5 人月）

自研 `CodeEditor` widget：
缓冲区（`ropey`）、视口虚拟化、行号/折叠栏、语法高亮（`ide-syntax` 的 tree-sitter 结果）、选区/多光标、方框/列选择、拖拽选择、双向文本、IME、剪贴板、撤销/重做、缩进与自动闭合、括号匹配、查找替换栏、粘性滚动、标尺、缩略图（可选）。

**验收**：打开 1 MB C++ 文件 ≤ 100 ms；按键到上屏 ≤ 16 ms（软件渲染）；10 万行文件滚动不掉帧越界；与 CodeMirror 版行为对照清单逐项通过。

### M3 · 编辑器 LSP 体验（3 人月）

补全弹窗、悬停、签名帮助、诊断（波浪线 + 面板）、inlay hints、语义高亮、代码镜头、折叠、面包屑、转到定义/引用/实现、重命名、格式化、代码操作、diff 视图、合并编辑器。

**验收**：clangd 全链路可用（与 CEF 版同一套 E2E 场景）。

### M4 · 功能迁移（10 人月，可 3–4 人并行）

按 §6 分组迁移 40 个 feature。每组含 UI + 交互 + 键位 + i18n + 截图回归。

### M5 · 对齐与发布（3 人月）

黄金截图回归、性能基准（含无 GPU 机器）、无障碍、IME 全输入法回归、打包（deb/AppImage，**不再带 CEF**，包体预计 < 60 MB）、三平台 CI、崩溃上报。

**合计 ≈ 24 人月（2 人年）**；3–4 人团队日历时间 **12–15 个月**。

## 9. 明确降级/不做的清单（需确认）

1. **Web 工具窗**（内嵌浏览器）——纯 Rust 无法提供，除非嵌入 CEF（与本方案目标冲突）。
2. **mermaid / ELK / cytoscape 图**——改 `canvas` 简易版或去掉。
3. **HTML 版 markdown 预览**——用 iced `markdown` widget，样式与现在不同。
4. **插件 UI 的 Web 形态**——现有插件系统允许 HTML 面板，迁移后需改为 Rust 扩展点。
5. **notebook 的富输出**（HTML/JS）——只保留文本/图片/表格输出。

---

## 10. 开工建议

1. 先做 **M0**（1–2 周，0.5 人月），拿到这台机器上的真实性能与 IME 数据。
2. M0 通过后按 M1 → M2 → M3 串行（编辑器是瓶颈，不能并行前置），M4 在 M2 完成后 3–4 人并行。
3. 每个里程碑结束做一次**决策门**：继续 / 调整范围 / 停止，避免沉没成本。
